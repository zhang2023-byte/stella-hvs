STELLA DEV CONSOLE

页面地图与操作指南

第一次运行只需要关注三个动作：载入配置、运行检查、点击启动。

推荐首跑

B-FULL · DEEPSEEK V4 PRO

固定 10 篇 dev 论文，Extractor 使用 deepseek-v4-pro，Reviewer 使用 glm-5.2。这个 preset 与项目冻结的首轮矩阵一致。

STEP BY STEP

第一次运行怎么操作

  1. 01
    载入推荐配置

    点击上面的按钮。系统会填入 Method B、正式 Run ID、两个模型、并发 3、Batch 8 和 deepseek provider。

  2. 02
    运行配置检查

    回到左栏点击“运行配置检查”。这一步不调用 LLM，只验证输入、凭据、规则版本和工作树。

  3. 03
    确认全部通过

    每一项前面都应是实心圆。若有失败，启动按钮会保持禁用，失败项会告诉你原因。

  4. 04
    启动 DEV RUN

    点击白色“启动 10 篇 DEV RUN”。这一步会产生真实 API 调用和 token 消耗。

  5. 05
    观察与调试

    在中间看论文和流程，在底部点事件，再在右侧检查模型请求、返回、工具操作和校验结果。

WHAT YOU ARE SEEING

顶部指标与流程节点

ELAPSED
当前运行已经持续多久。
INPUT / OUTPUT
累计输入和输出 token。
REASONING
Provider 报告的 reasoning token；不是隐藏思维文本。
CACHE HIT
重复上下文命中的缓存 token，通常能降低成本。
CTX → FINAL
从打包论文上下文、抽取、校验、修复、审阅到最终产物。
运行安全边界

“配置检查”不会调用外部模型；只有点击“启动 DEV RUN”才授权真实 LLM 调用。STOP 会保留已完成论文，随后可用同一配置 RESUME。
