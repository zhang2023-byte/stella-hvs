# Stella 0.6.0

Stella 0.6.0 hardens the V4 benchmark roster boundary without changing the
campaign, candidate-inclusion rules, scored quantities, or model routing.

- Method B and the retained agentic implementation use a deterministic
  paper-first roster context: sorted TeX, then declared ECSV evidence. Generated
  catalog JSON and `.bib`/`.bbl` files are excluded only from this roster stage;
  downstream extraction retains the complete context.
- The roster reviewer independently discovers a complete typed roster before
  seeing producer output. Code compares the two rosters; a mismatch permits one
  same-reviewer reconciliation and then seals or fails closed.
- ECSV display labels are normalized to canonical machine columns only for a
  unique exact mapping. Unknown or ambiguous labels remain validator errors.
- Workflow whole-response stages request structured JSON, roster submissions
  use strict schemas, and malformed JSON receives bounded correction feedback;
  Stella never guesses or repairs scientific values locally.

`benchmark.roster_bundle` advances to v3 and `benchmark.run_manifest` to v4.
Older versions remain readable history, while new formal B/C runs must contain
`roster_context_manifest.json`. Existing run archives are not migrated or
resumed under the new method fingerprint/cache identity.
