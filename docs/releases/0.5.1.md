# Stella 0.5.1

Release boundary prepared on 2026-07-19. Version truth remains
[`src/stella/schema_registry.py`](../../src/stella/schema_registry.py); this
note documents behavior and compatibility, not a second version registry.

## Summary

0.5.1 fixes the first general Method B/Core delivery defect found in the
post-architecture V3 dev validation. Candidate membership remains sealed by
the reviewed roster, while downstream batch generation now returns only the
ordered `record_id` anchors and candidate fields. After every count, order,
and record anchor matches, code restores the exact sealed identifier payload
before schema and paper-evidence validation.

## Behavior changes

- Batch prompts no longer ask the model to reproduce sealed names, Gaia IDs,
  aliases, or their source locators. The model returns the exact ordered
  `identifiers.record_id` anchors; code supplies the rest from the sealed
  roster.
- Candidate count, order, and `record_id` changes remain hard failures. No
  partial identifier restoration occurs when any anchor is wrong.
- Initial batch fill, validator-driven targeted repair, and final-review-driven
  repair share the same restoration path.
- Reports record bounded `sealed_identifier_hydration` events containing only
  changed field paths and counts. Exhausted initial batches now retain every
  rejection summary and a non-empty `batch_generation_failed` reason.

## Evidence

- Synthetic tests cover count/order/record-ID protection, initial batch fill,
  validator repair, final-review repair, bounded audit logging, and actionable
  exhausted-batch reports.
- Offline replay of the immutable hardened-B archives restored all identifier
  mismatches in the parseable `1902.05061` repair replies. The same replay
  reduced each of the three `2401.02017` first-batch replies from eight sealed
  identifier mismatches to zero without changing candidate count, order, or
  record IDs.
- No LLM/API request or private-gold read is part of this fix or its tests.

## Compatibility and migration

- This is a patch release. Persisted artifact schemas, the active
  `hvs-extraction-v3` campaign, candidate meaning, scoring, and gold remain
  unchanged; no migration is required.
- Historical run responses, reports, manifests, seals, and scorecards remain
  immutable. The changed prompt and implementation receive new component
  hashes, so any future experiment must use a fresh run ID and cannot be
  presented as a continuation of an old run.
- Citation choice, scientific values, units, limit kinds, inclusion decisions,
  and compact candidate-range interpretation remain model/expert work. Code
  does not silently repair them.

## Next gate

The fix addresses delivery failures in `1902.05061` and `2401.02017`; it does
not resolve the scientific candidate boundary exposed by `2209.03560` or the
dense grouped-candidate interpretation in `1804.10179`. Those remain Task 6
expert decisions before any new cold-cache B/Core dev run. The 40-paper test
split remains locked.
