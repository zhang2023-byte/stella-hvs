# Stella 0.5.0

Release boundary prepared on 2026-07-18. Version truth remains
[`src/stella/schema_registry.py`](../../src/stella/schema_registry.py); this
note documents behavior and migration, not a second version registry.

## Summary

0.5.0 makes Method B with `core_prov` the only active direct benchmark path and
moves Method C and FULL enrichment behind explicit legacy opt-ins. It also
completes the V3 provenance/CORE delivery hardening and preserves the first
post-architecture hardened-B scorecard as a non-passing validation result.

## Behavior changes

- `run_benchmark_extraction.py` defaults to `core_prov`; FULL requires
  `--allow-legacy-full`.
- `run_agentic_extraction.py` is a legacy reproduction interface. Every Method
  C run requires `--allow-legacy-method-c`; C + FULL also requires
  `--allow-legacy-full`.
- The dev console creates only Method B/Core experiments. Historical Method C
  and FULL runs remain visible but are read-only, non-resumable, and
  non-retryable.
- The active `benchmark_extraction_run` workflow accepts only Method A or
  Method B and never supplies legacy flags.
- run-manifest v3 records separate CORE/enrichment delivery envelopes and seal
  checks complete component hashes before reading outputs.
- roster-bundle v2 binds shared-cache identity to reviewer provider as well as
  model/prompt/rules, requires contiguous ordered record IDs, and rejects a
  `revised` decision with no challenge.

## Persisted results

The public V3 dev scorecards at this boundary are:

- `v3-dev-baseline-b-core-r1`: 8/10 valid, L1 F1 0.593, L2 end-to-end 0.556.
- `v3-dev-baseline-c-core-r1`: 6/10 valid, L1 F1 0.226, L2 end-to-end 0.406.
- `v3-dev-hardened-b-core-r1`: 7/10 valid, L1 F1 0.286, L2 end-to-end 0.248.

The incomplete `v3-dev-hardened-c-core-r1` archive has six paper reports but
is deliberately unsealed and unscored. It is retained as local legacy evidence
and is not a release result.

## Compatibility and migration

- Existing run manifests, scorecards, C/FULL archives, and trace records are
  immutable historical artifacts. No migration or in-place rewrite is needed.
- Readers continue to accept supported historical artifact versions through
  the schema registry and compatibility adapters.
- Automation that created Method B without `--task-surface` now receives Core
  rather than FULL. Pin `--task-surface core_prov` for clarity.
- Automation that intentionally reproduces Method C or FULL must add the
  corresponding legacy flag and use a fresh run ID. Normal production or formal
  experiment automation should remove C/FULL instead.
- Private gold, run archives, private scoring details, and report HTML remain
  outside commits; only public manifests, releases, and scorecards are durable
  repository artifacts.

## Next gate

0.5.0 does not declare the roster-review architecture scientifically accepted.
The hardened-B regression must first be diagnosed per paper and stage, followed
by expert Task 6 adjudication and one isolated cold-cache B/Core dev repeat.
The 40-paper test split remains locked until that method is frozen and a test
release is explicitly authorized.
