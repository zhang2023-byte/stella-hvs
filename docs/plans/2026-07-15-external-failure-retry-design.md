# Benchmark 外部故障重试设计

## 目标

让开发工作台可以打开历史 Run，并把“重试”严格限定为未封存 Run 中明确由外部模型服务传输失败导致的论文。工作台不是通用的旧 Run 修复器：工作流、校验、复核、运行器或数据契约问题必须先修代码，再新建实验。

## 不变量

- `run_manifest.json` 存在时，Run 已封存，所有操作只读。
- 成功状态 `ok` 和 `ok_with_cjk_warnings` 永不重跑。
- `report.json.status` 必须精确等于 `transport_error`，并且错误须能保守识别为外部服务故障（网络/超时、401/403/408/425/429 或 5xx）。HTTP 400 等请求错误和无法分类的传输错误不可重试。
- 单篇重试只运行被确认的论文；批量重试只运行当前有资格的论文，不包含成功、缺失或其他失败。
- 重试沿用原 Run 的不可变 `run_config.json`，保留完整 dev split 和方法指纹；旧失败目录移入 `_failed_attempts/` 后才启动新尝试。
- 重试仍执行正式 Run 的清洁工作树、生成视图、凭据和进程锁检查，并由浏览器显式确认授权真实 API 调用。

## 后端契约

`run_contract.py` 提供一个窄接口，先验证封存状态、论文成员关系、`transport_error` 状态和外部故障分类，再归档指定论文。两个正式 runner 新增可重复的 `--retry-external-paper` 参数：它只能与 campaign dev/test 选择和既有 Run 一起使用，并只处理参数指定的论文，同时 `run_config.json.expected_papers` 仍保持完整 campaign split。

开发工作台的 Run 摘要为每篇论文返回 `retry_eligible` 与不可重试原因，并在 Run 层返回 `sealed`、`retryable_papers`。POST 接口分为单篇和全部外部故障两种；服务器在启动前重新计算资格，前端状态不能绕过后端检查。

## 界面行为

- 历史 Run 页面清楚标注“已封存，只读”或“未封存”。
- 论文详情只对已确认属于外部服务故障的 `transport_error` 显示“重试这篇论文”。
- Run 工具栏只在存在可重试论文时显示“重试全部外部故障（N）”。
- 校验、复核、运行器等错误显示“需修改工作流后新开实验”，不显示重试按钮。
- 两种重试都需要确认，确认文案说明将归档旧尝试并产生真实 API 调用。

## 验证

- 单元测试覆盖封存、成功、非传输错误、非 Run 成员和合格传输错误。
- HTTP/API 测试覆盖权限确认、路由和最终 runner 参数。
- 前端测试覆盖按钮可见性、封存只读和非外部错误无入口。
- 运行 Python 全量测试、前端测试与生产构建，不实际调用外部服务。
